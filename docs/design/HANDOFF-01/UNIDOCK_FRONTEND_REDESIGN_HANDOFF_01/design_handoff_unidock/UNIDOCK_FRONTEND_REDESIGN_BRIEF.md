# UniDock Frontend Redesign — Design Brief（修订版）

> 供 Claude Design 使用。文档仅描述设计目标、约束与现状事实，不包含任何代码实现指令。

---

## 0. 文档使用说明

- 本文档是 UniDock 前端重写阶段的**主要书面设计输入之一**。Claude Design 还应结合 UniDock 品牌资产、当前网站 web capture、必要截图与代码库理解现有产品。
- "已验证的现状事实"基于真实生产环境 (https://www.unidock.cn) 的实地审查与 DOM/样式抓取。
- 标注"需要后续真实设备验证"的结论来自 iframe 模拟（受 Windows 系统对 Chrome 窗口最小宽度的限制），仅作为问题线索，不能作为最终验收依据。
- 任何在文档中标注为"待人工确认"的内容均不属于必做范围，需由产品方批准后才能进入设计稿。

## 1. 产品定位（已确认）

- **UniDock 是连接新生信息、校园资源与相关服务的校园服务入口**。
- UniDock **不是**：学校官网、企业 SaaS 后台、商业营销落地页。
- 核心用户：NUIST 新生（入学前、报到当天、入校初期均覆盖）。
- 核心价值：把新生入学最高频的信息入口、流程指引和负责人联系方式整理在一处，降低重复检索成本。

## 3. 必须修复的问题

### 3.1 文案与语义错误（已实地验证）

- **"报道全流程"应为"报到全流程"**：详情页 hero、面包屑 chip、行前准备页底部 CTA "查看报道全流程" 均使用错别字"报道"；首页卡片使用的是正确的"报到"，两边不一致。设计阶段需在画布中确保此页面 hero、chip、相关 CTA 在中文与英文模式下均显示为正确文案。

### 3.2 国际化漏洞（已实地验证）

- 报到流程详情页切到 EN 后，仅"Back to Home"被翻译，hero、阶段卡、路线卡、行车提醒等仍为中文，造成中英混排断层。设计稿需呈现该页面的英文版本完整状态。
- 联系负责人页内"复制"按钮文案在 EN 模式仍为中文。设计稿需提供该按钮的中英文两个版本。
- 英文首页 hero 因字数远多于中文，桌面与手机端均出现极高的竖排折行（6–7 行），未做语言相关字号自适应。设计稿需呈现英文 Hero 的合理表现。

### 3.3 顶部导航不一致（已实地验证）

- 首页 TopBar：U-avatar + 标题 + ≡（单行）。
- 部分详情页前置"返回首页"按钮。
- Mailbox 在 ≡ 右侧显示"站内信箱"label，Better Service 显示"Better Service"label，报到全流程详情页则不显示 label。
- 右上"Better"按钮与侧栏中的"Better Service"指向同一目标但使用了两种样式。
- 邮件红点、Better 按钮的提醒规则未文档化，跨页表现不统一。

### 3.4 页面留白与节奏（已实地验证）

- 首页 hero 与 #core-entry 之间存在超过一个屏高的空白段。
- 校内系统导航在内容块后出现大段空白。
- Better Service 当前页面仅 1 张内容卡，独占整页。
- 行前准备页"不要带 / 可以后补"在桌面端使用了 50/50 宽栏，但内容量小，视觉占比过大。

### 3.5 视觉一致性细节（已实地验证）

- 不同卡片间圆角、阴影、内边距存在轻微不一致（首页大卡 vs 校内系统二列卡）。
- Hero 字号在所有视口使用同一数值，未做视口或语言相关缩放。

### 3.6 交互反馈缺失（已实地验证）

- 联系负责人页"复制"按钮无 toast / 状态反馈。

### 3.7 移动端布局问题（需要后续真实设备验证）

> 以下结论基于 iframe (390 px 宽) + 真实 CSS media query 的间接模拟，受 Windows 系统下 Chrome 窗口最小宽度限制无法做原生小屏测试，**必须在真实设备上复测后再作为验收依据**。

- 详情页顶部导航在移动端会换为两行（"返回首页 / 邮件 / Better / 地球-中-EN" 一行，"U-avatar + UniDock + ≡" 另一行），整体顶栏高度过高，吃掉首屏。
- 顶栏右侧的"邮件 / 地球-中-EN"在 390 px 视口下被右边界裁切。
- "UniDock" 文字与 ≡ 之间外边距过小，视觉上几乎贴在一起。
- 首页 hero 行数在移动端过多，CTA 被推到 fold 之下；英文模式更严重。
- 首页"你需要的入口"区块与下方"核心入口"之间在移动端出现 600+ px 的纯空白段。

## 4. 必须保留的品牌与产品资产

> 这些资产**在视觉重写后必须仍然可识别**，但允许在表现形式、字重、配色细节上做合理优化。

1. **冷银色极简 U 图标**：保持中性、克制、可作为品牌识别核心。
2. **柔和渐变背景**（浅蓝 → 米橙）：作为全站统一底色继续使用。
3. **中英双语**：所有页面、所有组件、所有可见文案都必须有中文与英文两个版本。
4. **移动端适配**：必须支持桌面、平板、手机三档视口。
5. **克制动效**：不引入炫技动画、复杂插画、视频背景或大块彩色图形。
6. **首页 01–07 编号入口顺序**：作为重要产品语言保留——顺序、编号呈现方式、"先用什么 / 再用什么"的隐含信息架构不得打乱。
7. **白卡 + chip + 大字 + → 指示**的内容卡范式可作为基础模板继续演化。
8. **联系负责人页一键复制**的产品行为继续保留。
9. **Mailbox 通过红点提示用户存在未读站内更新**的产品行为继续保留。
10. **Redirect 中转页"主入口 / 次入口"二选一**的产品行为继续保留。

## 5. 本次前端重写的设计目标

1. **统一视觉语言**：建立一套完整的设计 token（颜色、半径、阴影、字号、卡 padding、间距比例），覆盖所有页面与所有组件。
2. **修正信息节奏**：每个首屏与每个滚动屏都有清晰的视觉锚点，避免大段无信息空白；信息密度与产品定位（克制、目录化）保持一致。
3. **重排响应式表现**：桌面、平板、手机三档下都能呈现清晰、可读、不被裁切的布局；中英两种语言下 Hero、卡片、TopBar 的表现均合理。
4. **统一顶部导航**：单一规则覆盖所有页面（首页 / 详情页 / 移动端），消除当前的多套 TopBar。
5. **解决文案与国际化的明显缺漏**：让中文与英文在视觉、布局、字号上达到同等品质。
6. **强化交互反馈**：所有需要用户操作的元素（复制、标记已读、跳转）都有可见反馈。
7. **保留并强化品牌识别**：在重写后第一眼仍能识别为"那个克制、整洁、信息清楚的 UniDock"。

## 7. 明确不在本次范围内的事项

- **不得改变现有业务逻辑、数据结构、后端接口或功能范围**。
- **未经人工确认的新功能不得进入最终必做设计稿与验收范围**。Claude Design 可以在独立、明确标注"待人工确认"的可选探索方案中提出新功能建议（见 §11），但这些方案不得混入主设计稿。
- **Chatbot / Agent / AI 助手不属于本次范围**——不得在任何页面预留浮动入口、按钮、抽屉、对话面板或占位组件。
- 不得引入与现有内容无关的营销组件（轮播图、视频背景、社交分享条、订阅弹窗等）。
- 不得改变 UniDock 的产品定位（不要把它做成学校官网、SaaS 后台或营销落地页）。
- SEO 元信息、HTML 模板抽取、i18n CI 校验、构建管线优化等属于**代码实现阶段**关注事项（见 §12），不属于 Claude Design 的核心设计要求。

## 8. 页面家族与可复用模板

### 8.1 建议的页面家族（5 类）

1. **Hub 页**（首页）—— 模块化纵向 section：Hero + 速通卡 + 编号入口 + 价值阐述 + CTA + 底栏。
2. **Guide 详情页**（报到全流程 / 行前准备 / 避坑 / 校内系统）—— 长文 + 章节锚点。
3. **Card Grid 页**（Better Service）—— 卡片矩阵，支持后续按类别扩展。
4. **Action 页**（联系负责人 / 合作联系 / Redirect 中转）—— 单一行动目标，组件极简。
5. **Feed 页**（Mailbox）—— 按时间倒序列出更新，含置顶、已读 / 未读、空 / 加载 / 错误状态。

### 8.2 应当沉淀为统一组件的元素

- TopBar（首页 / 详情 / 移动三态合一）
- SideDrawer
- HeroBlock（含字号档位）
- EntryCard（编号 + chip + 标题 + 描述 + 箭头）
- StepCard（阶段）
- ChecklistCard（必备 / 易遗漏）
- KeyValueCard（带复制按钮 + 反馈）
- Callout（info / advice / warn 三种语义）
- TimelineList（用于报到全流程）
- RedirectCard（主入口 / 次入口）
- UpdateRow（Mailbox 行项，含已读 / 未读 / 置顶状态）
- Empty / Loading / Error 状态模板

## 9. 桌面端、移动端与中英双语要求

### 9.1 桌面端

- 主断点 ≥ 1024 px 与 ≥ 1440 px 两档需有合理表现。
- Hero 大字字号需要在 ≥ 1440 时有节制，避免视觉过度恢宏。
- 卡片栅格在 ≥ 1024 时建议 2–3 列；在 1024–1280 之间避免出现稀疏的 3 列。

### 9.2 移动端

- 必须覆盖 320 / 360 / 375 / 390 / 414 五个常见小屏宽度。
- TopBar 在 ≤ 414 px 时建议单行高度 ≤ 56 px，且右侧操作不被裁切。
- Hero 字号需较桌面端缩小；行数上限不超过 5 行。
- 卡片列在 ≤ 640 px 时统一 1 列。
- 移动端必须能在 iOS Safari、Android Chrome 真实设备上验证后再交付。

### 9.3 中英双语

- 所有**用户界面**文案、按钮、chip、callout、状态标签、导航与操作反馈必须提供中英文版本。
- 英文版本的字号需有一档独立的语言相关缩放（针对英文字数普遍多于中文的情况）。
- 复制按钮、可见的 page title 标签、空 / 加载 / 错误状态文案在英文模式下不得保留中文。
- 两种语言下 Hero 的视觉高度差应控制在合理范围（建议英文不超过中文 1.5 倍）。
- **Mailbox 公告标题与正文是否双语取决于现有内容数据**——设计稿不强制改变数据结构或内容生产方式；设计阶段只需保证 Mailbox 的容器、状态标签、操作按钮、空 / 加载 / 错误提示在双语下表现一致。

## 10. 供 Claude Design 使用的设计约束

1. 保持 UniDock 的克制、整洁、目录化气质——任何视觉装饰都要服务于"减少信息查找成本"。
2. 不引入彩色插画、3D 渲染、大幅照片、动态背景、视频或炫技动画。
3. 动效仅限于克制的微交互（hover、focus、复制成功 toast、抽屉展开、滚动揭示）。
4. 字体系统继续使用一套中英共用的 sans，不引入装饰字体。
5. **配色基调**：保留白卡、深灰文字、柔和蓝橙渐变背景的品牌气质。主操作色可以在克制、中性、可信的范围内优化，不必强制锁定为当前的深紫色；任何替代选择都需要保持与品牌气质一致。
6. 阴影系统建议低强度、统一一档基础阴影 + 一档悬浮阴影。
7. 圆角系统建议 12 / 16 / 24 三档为主，不混用更多数值。
8. 所有图标使用线性、克制的几何风格；不使用彩色拟物图标。
9. 信息层级必须能在一眼之内被读取，避免次要信息抢占主标题层级。
10. **视觉锚点**：主要内容区块与长留白区段需要具备合理的视觉锚点（编号、icon、引用、时间轴、装饰线等可酌情使用）。不要求每一张卡片都额外添加锚点装饰，避免过度装饰；目标是消除大段无信息空白，而非堆砌细节。

## 11. 可探索但必须经过人工确认的设计方向

> 这些方向**不属于必做范围**。Claude Design 在主设计稿之外可以提出可选探索方案，但必须明确标注"待人工确认"，由产品方决定是否采纳。可选探索方案不得混入主设计稿与验收范围。

- 将侧边抽屉与首页 01–07 编号入口建立 1:1 对应关系。
- 在首页加入按阶段进入的视觉导航条（如"入学前 / 出发当天 / 入校后"），与子页面建立深链对应。
- 顶部"Better"按钮的去留与新形态。
- Better Service 的产品定位升级（例如卡片矩阵 + 类别筛选）。
- Better Service 的任何新增功能（筛选、订阅、内部审计字段、状态分组、权限提示等）。
- Mailbox 的任何新增功能（独立详情页、分类、订阅、筛选、按时间分组、归档、批量标记等）。
- 语言切换按钮的形态简化（例如从三段胶囊改为单按钮）。
